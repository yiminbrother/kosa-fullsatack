# 회원 아이디 검증

회원 가입 DTO의 `mid` 또는 사용자가 지정한 회원 아이디 필드에 다음 규칙을 적용한다. 사용자가 다른 규칙을 명시하면 그 요청을 우선한다.

- 필수 입력이며 길이는 5자 이상 20자 이하이다.
- 첫 글자는 영문 대문자 또는 소문자이다.
- 영문 대문자 `A-Z`를 최소 1자 포함한다. 소문자는 필수가 아니다.
- 특수기호 `!` 또는 `_` 중 하나 이상을 최소 1개 포함한다. 두 종류 모두 포함할 필요는 없다.
- 허용 문자는 영문 대소문자, 숫자, `!`, `_`뿐이다. 숫자는 필수가 아니다.
- 공백, 줄바꿈, 한글 및 다른 특수기호는 허용하지 않는다.

## 적용

대상 DTO와 기존 검증 어노테이션을 먼저 확인하고, 중복되거나 충돌하는 제약은 정리한다. 프로젝트가 사용하는 Jakarta 또는 javax 패키지에 맞춰 import한다. Jakarta 프로젝트의 기본 구현은 다음과 같다.

오류 메시지의 대상 이름은 프로젝트의 기존 표현이나 사용자가 지정한 실제 필드명을 따른다. 별도 기준이 없으면 "회원 아이디"를 사용한다. 예제의 `mid`를 다른 필드에 적용할 때 필드 선언과 오류 메시지를 대상에 맞게 조정한다.

```java
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

@NotBlank(message = "회원 아이디는 필수 입력 정보입니다.")
@Size(min = 5, max = 20, message = "회원 아이디는 5자 이상 20자 이하여야 합니다.")
@Pattern(
    regexp = "(?=.*[A-Z])(?=.*[!_])[a-zA-Z][a-zA-Z0-9!_]*",
    message = "회원 아이디는 영문자로 시작하고, 대문자와 특수기호(! 또는 _)를 각각 1자 이상 포함하며, 영문자, 숫자, !, _만 사용할 수 있습니다."
)
private String mid;
```

`@Pattern`은 전체 문자열을 검사한다. 첫 번째 전방 탐색은 대문자 포함을, 두 번째 전방 탐색은 허용 특수기호 포함을 검사한다. 길이는 `@Size`, null과 빈 값은 `@NotBlank`가 담당한다.

요청된 필드 검증 범위로 수정한다. 요청 처리 시 실제 검증 실행 여부까지 다루는 작업이라면 컨트롤러의 기존 `@Valid` 또는 `@Validated` 적용도 확인한다.

## 검증 기준

변경 범위에 맞는 컴파일 또는 기존 검증 테스트로 확인한다. 동작을 확인할 때 다음 경계 사례를 활용한다.

- 통과: `Abcd!`(5자), `abcd_E`(소문자 시작), `A1234567890123456789!`(20자).
- 실패: `Abc!`(4자), `A12345678901234567890!`(21자), `1Abc!`(숫자 시작), `_Abcd`(특수기호 시작).
- 실패: `abcd!`(대문자 없음), `Abcde`(특수기호 없음), `Abcd@`(허용되지 않은 기호), 공백이나 줄바꿈이 포함된 값, null, 빈 문자열.
